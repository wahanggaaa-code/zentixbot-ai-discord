# Dashboard web — inventaris integrasi

Inventaris kode per perubahan dashboard ini, bukan sertifikasi produksi. **Live** di bawah berarti halaman memiliki jalur ke bot/API saat dashboard disajikan bot melalui `/dashboard/`; ia tetap memerlukan login Discord, izin, database dan layanan pendukung. Pengujian lokal memakai PostgreSQL disposable, Discord tiruan dan jsdom; event keluar juga diuji dengan pengiriman Discord tiruan. Belum membuktikan OAuth, Discord, Lavalink, provider, Neon atau Wispbyte pada deployment sebenarnya. Preview statis (`dashboard-preview/` disajikan sendiri) hanya simulasi; jangan masukkan rahasia atau data pribadi.

## Goodbye non-AI

Buka **Fitur bot → Welcome & verification → Goodbye** pada dashboard bot yang telah login. Admin server dapat memilih channel, pesan, ping, gambar HTTPS dan tampilan embed. Pratinjau hanya contoh lokal, tidak mengirim pesan atau memuat URL gambar. Bot memakai teks biasa jika tidak memiliki izin embed. URL gambar dikirim ke Discord ketika pesan dikirim; jangan gunakan URL yang mengandung rahasia atau token. Pengaturan ini berbagi record PostgreSQL dengan welcome dan autorole; ketika AI Goodbye aktif, AI Goodbye menggantikan pesan non-AI ini. Cek izin channel dan konfigurasi AI sebelum mencoba langsung.

API `GET /dashboard/api/bot/goodbye` dan `PATCH /dashboard/api/bot/goodbye` memakai autentikasi dashboard; PATCH juga memerlukan Origin dan CSRF valid. Saat menyimpan, transaksi mengunci guild lalu welcome dan menolak revisi yang usang. Perubahan welcome melalui bot atau dashboard membuat revisi goodbye usang; salin perubahan yang belum disimpan, muat ulang, lalu terapkan kembali. Pemeriksaan revisi berbasis isi tidak mendeteksi A→B→A dan tidak memaksa SQL langsung/bot lama mengikuti aturan. Data goodbye yang bentuknya rusak ditolak untuk ditinjau, tidak di-reset. Jika koneksi putus saat commit, hasil penyimpanan bisa tidak diketahui; muat ulang dan periksa sebelum mengulang. Field lain pada record dipertahankan. SQLite belum didukung untuk halaman ini dan tetap ditunda.

Tidak ada tombol tes Discord dalam integrasi ini. Discord dan PostgreSQL tidak berada dalam satu transaksi; pesan dapat gagal, event dapat terduplikasi, dan event join/leave lama masih punya fallback default ketika pembacaan database gagal. Pengujian langsung di server uji, serta prosedur pemulihan dan hosting, masih diperlukan sebelum produksi.

## Birthday

Buka **Fitur bot → Birthday** pada dashboard bot yang diautentikasi. Owner atau administrator dapat memilih channel teks untuk pengumuman atau memilih **Nonaktif**. Server memeriksa izin View Channel, Send Messages dan Embed Links saat menyimpan, tetapi izin dan keberadaan channel dapat berubah kemudian. Scheduler bot memakai tanggal **UTC** dan pengaturan channel ini; role birthday opsional tetap diatur di luar halaman ini. Saat channel dinonaktifkan, scheduler juga melewati pembersihan role birthday pada siklus itu; periksa role secara manual bila perlu. Menyimpan tidak mengirim pesan percobaan atau menjamin scheduler berjalan.

Daftar menampilkan ID serta hari/bulan maksimal 50 per halaman, tanpa tahun. Owner/admin dapat mengubah atau menghapus entri yang sudah ada setelah konfirmasi; fitur ini memberi admin kemampuan mengubah data anggota lain, jadi pastikan ada dasar dan izin yang sesuai. Penambahan entri baru melalui web dan riwayat audit khusus perubahan Birthday belum tersedia. Pengubahan memeriksa keanggotaan melalui Discord; penghapusan entri aktif tetap dapat dilakukan tanpa pemeriksaan itu. Penghapusan ini bukan penghapusan menyeluruh dari backup database atau salinan lain. Ini data pribadi: akses dibatasi owner/admin, respons no-store, dan tidak tersedia di preview statis. Data bisa berubah antarhalaman atau tampak sementara tidak lengkap jika penulis bot lama masih aktif; halaman bukan snapshot atau backup. Data tanggal tidak valid pada halaman ditolak untuk ditinjau. Jangan bagikan screenshot atau ekspor tanpa kebutuhan dan izin.

API `GET /dashboard/api/bot/birthday/settings`, `PATCH /dashboard/api/bot/birthday/settings`, `GET /dashboard/api/bot/birthday/list` dan `PATCH /dashboard/api/bot/birthday/member/:userId` memerlukan autentikasi; PATCH memerlukan Origin dan CSRF. PATCH pengaturan channel mengunci record guild lalu welcome dan menolak jika channel yang dilihat sudah berubah. Deteksi berdasarkan nilai channel tidak mendeteksi A→B→A; penulis SQL langsung atau bot lama dapat mengabaikan penguncian. Perubahan bidang lain dipertahankan. Jika status commit tidak diketahui, muat ulang dan periksa sebelum mencoba lagi. SQLite belum didukung.

**Jangan gunakan daftar sebagai bukti data aman:** versi lama bot memakai read-modify-write seluruh daftar dan DELETE/INSERT tanpa transaksi. Jalur bot versi ini memakai transaksi per anggota, termasuk perpindahan cadangan saat keluar/bergabung, dan menolak mutasi map melalui API generik. Hal ini hanya melindungi penulis yang mengikuti aturan tersebut: hentikan semua instans versi lama sebelum upgrade, dan jangan jalankan migrasi atau SQL manual bersamaan. Tidak ada perbaikan otomatis untuk data yang sudah hilang. Backup dan prosedur pemulihan yang diuji tetap diperlukan. Tes scheduler menggunakan Discord tiruan, bukan pengujian penjadwalan atau pengiriman live.

Transaksi Birthday PostgreSQL mengunci guild dan memperbarui satu anggota. Saat memindahkan atau memulihkan, backup yang rusak, berakhir masa berlaku, atau berbenturan dengan tanggal aktif ditolak untuk ditinjau tanpa overwrite. Data legacy birthday yang ambigu juga ditolak saat operasi. Kegagalan event keluar/bergabung dicatat tetapi tidak dicoba ulang otomatis; event yang hilang atau diterima tidak berurutan masih perlu pemulihan manual. `/birthday list` dan `/birthday next` tidak lagi menghapus tanggal hanya karena Discord gagal menemukan anggota. Penyimpanan backup bukan pengganti backup database, dan hasil commit ketika koneksi terputus bisa tidak diketahui. Perintah `/birthday set` lama masih menolak 29 Februari pada tahun yang bukan kabisat, walaupun format penyimpanan dapat menyimpannya.

Saat edit/hapus tanggal, API menolak jika entri sudah berubah atau hilang sejak daftar dimuat, jika backup anggota keluar masih ada, atau jika data legacy ambigu. Setelah konflik, muat ulang; jangan menimpa tanpa pemeriksaan. Pemeriksaan tanggal berbasis nilai tidak mendeteksi perubahan A→B→A. Pengecekan anggota Discord tidak atomik dengan transaksi database; anggota dapat keluar sesudah pemeriksaan. Event keluar/bergabung dan operasi dashboard yang memakai versi ini berbagi kunci transaksi; instans lama atau SQL langsung tidak dilindungi. Hasil commit yang terputus bisa tidak diketahui. Halaman daftar memeriksa konflik legacy dalam snapshot baca per halaman, tetapi bukan snapshot stabil antarhalaman.

Web menerima 29 Februari. Scheduler hanya mengumumkannya pada 29 Februari UTC; tidak ada pengumuman otomatis pada tahun non-kabisat. Perintah `/birthday set` masih mempunyai validasi berbeda untuk tanggal tersebut dan perhitungan upcoming lama dapat berbeda; jangan menganggap perilakunya seragam.

### Audit awal Giveaway untuk integrasi berikutnya

Aksi Giveaway melalui web belum tersedia. Jalur PostgreSQL lama `saveGiveaway`/`deleteGiveaway` membaca seluruh map lalu menyimpannya kembali; adapter `guild_giveaways` menghapus dan memasukkan kembali seluruh baris guild. Dua penulis bersamaan dapat menimpa perubahan, dan kesalahan di antara operasi dapat meninggalkan data tidak lengkap. Efek edit/kirim pesan Discord juga terpisah dari commit database; helper penanda delivery saat ini khusus SQLite. Karena itu jangan membuka tombol create/end/reroll/delete di web sebelum menata ulang semua penulis PostgreSQL yang relevan, menyelesaikan strategi konflik dan rekonsiliasi efek Discord, dan menguji perlombaan/kegagalan. Ini temuan audit awal, bukan jaminan daftar seluruh masalah Giveaway sudah lengkap.


### Daftar Giveaway (hanya baca)

Buka **Fitur bot → Giveaway** setelah login Discord sebagai owner atau administrator. Halaman mengambil maksimal 50 baris setiap kali dari tabel PostgreSQL `giveaways` untuk server yang dikonfigurasi, berurutan menurut ID pesan (bukan waktu). Daftar menampilkan hadiah, ID pesan/channel/host, status, penanda pengiriman jika tersimpan, dan jumlah entri tersimpan. Identitas peserta maupun pemenang tidak dikirim ke browser. Respons dibatasi no-store; data cacat/berukuran besar ditandai untuk diperiksa dan ID baris yang tidak valid menolak halaman itu. Preview statis tidak mengakses database.

Tampilan adalah inventaris tersimpan, **bukan bukti kondisi Discord atau hasil final**. Angka entri menghitung elemen yang disimpan, bukan bukti peserta unik/layak; waktu berasal dari JSON dan ditampilkan pada zona waktu browser. Kolom waktu PostgreSQL untuk scheduler bisa berbeda dan belum diverifikasi pada halaman. Pesan Discord dapat hilang, status dapat tertunda atau tidak cocok, dan daftar dapat sementara kosong/tidak lengkap selama proses penulis lama menghapus lalu memasukkan data. Paging bukan snapshot lintas permintaan. Peringatan legacy hanya memeriksa key persis `guild:<id>:giveaways` pada `temp_data` dan `cache_data`, bukan audit semua key atau backup. Periksa Discord dan penyimpanan sebelum bertindak.

Audit juga menemukan scheduler PostgreSQL yang memodifikasi pesan sebelum menandai hasil di database, sehingga kegagalan/proses paralel bisa menimbulkan keadaan atau pengumuman yang tidak konsisten. Operasi Giveaway web belum disediakan sampai semua jalur terkait direkayasa dan diuji, termasuk pendaftaran, penguncian, pilihan pemenang dan rekonsiliasi pengiriman; lihat juga audit awal di atas.

Fondasi transaksi Giveaway PostgreSQL telah dibuat dan diuji secara terisolasi, tetapi **belum terhubung ke runtime atau aksi web**. Risiko jalur bot lama di atas masih berlaku. Detail dan prasyarat cutover: `DOKUMENTASI-GIVEAWAY-PG.md`.
