# Progres proyek ZentixBot dan dashboard

- **Tanggal inventaris:** 12 November 2026 (WIB)
- **Repositori kerja:** `zentixbot-bot-only`
- **Basis kode yang ditinjau:** commit `98b2bee`
- **Pembaruan terakhir:** 13 November 2026, branch `arena/7ea7d915-zentixbot-ai-discord` di repositori `zentixbot-ai-discord` (lihat bagian 8). Tiga baris di atas menggambarkan inventaris awal.
- **Tujuan:** mengintegrasikan fitur bot ke dashboard web secara bertahap, dengan penyimpanan dan operasi Discord yang aman untuk jalur yang digunakan.

> **Kesimpulan singkat:** dashboard sudah mempunyai banyak jalur terhubung ke bot, tetapi integrasi seluruh fitur **belum selesai** dan proyek **belum dinyatakan siap produksi**. Join to Create di sisi bot sudah memakai satu protokol transaksi PostgreSQL untuk semua penulisnya dan belum pernah diuji di Discord sungguhan; dashboard dapat mengubah pengaturan trigger, sedangkan inventaris channel sementara tetap baca-saja. PostgreSQL adalah backend runtime saat ini. SQLite masih eksperimental dan belum bisa digunakan sebagai backend runtime.

## 1. Cara membaca status

- **Terhubung sebagian:** kode dashboard memiliki jalur ke bot/API untuk fungsi yang disebutkan. Ini tidak berarti semua fungsi kategori sudah selesai atau layanan eksternal sudah diuji langsung.
- **Baca-saja:** halaman dapat membaca data, tetapi tidak menyediakan perubahan data untuk area tersebut.
- **Prototipe:** kode dan tes tersedia untuk pengembangan, tetapi belum digunakan oleh runtime bot atau alur dashboard yang aktif.
- **Belum:** fitur/operasi belum dibuat, belum diaudit, atau sengaja dinonaktifkan karena belum aman.

Preview statis `dashboard-preview/` yang dibuka sendiri adalah **simulasi**. Akses yang terhubung membutuhkan dashboard yang disajikan bot melalui `/dashboard/`, login Discord, izin dan layanan yang relevan. Pengujian sejauh ini memakai database lokal, Discord/provider tiruan dan jsdom; itu bukan bukti deployment nyata berhasil.

## 2. Ringkasan pekerjaan yang sudah dilakukan

- Struktur dashboard web, login Discord dan API untuk berbagai fitur telah dikembangkan. Akses dashboard memakai pemeriksaan owner/admin server; beberapa area AI atau operasi sensitif memiliki pembatasan tambahan untuk bot owner. Jalur perubahan yang relevan memakai Origin dan CSRF.
- Jalur PostgreSQL diperkuat: pemeriksaan startup, versi dan kelengkapan skema, audit key legacy yang dikenal, TLS dengan verifikasi, serta `/health` dan `/ready` dengan fungsi yang berbeda.
- Penguncian/transaksi dan pemeriksaan konflik telah ditambahkan pada jalur tertentu untuk konfigurasi guild/welcome, verification, Birthday, warning, tiket, ekonomi dan Giveaway. Jaminan hanya berlaku bagi jalur yang benar-benar mengikuti protokol dan diuji.
- Backup PostgreSQL dan latihan restore ke target uji terpisah tersedia. **Restore produksi masih dinonaktifkan.**
- Dashboard Giveaway sudah memiliki daftar, pembuatan, akhiri/undi ulang, penghapusan dan perbaikan pengiriman tertunda dengan pengaman; Join to Create sudah memiliki pengaturan trigger lewat web, inventaris baca-saja dan pemeriksaan Discord untuk ID pending yang tercatat.
- SQLite kini database bawaan: tanpa koneksi PostgreSQL yang diatur, bot membuat dan memakai berkas `data/zentix.db`. Diuji lokal saja; belum pernah dijalankan di hosting atau Discord sungguhan. Data PostgreSQL tidak dipindahkan.
- Workspace telah dirapikan dan sembilan arsip ZIP yang ditemukan telah dihapus sesuai permintaan. Kode proyek, gambar unggahan, direktori referensi dan hasil pengujian akhir dipertahankan. Penghapusan ZIP tidak membuktikan bahwa seluruh backup atau salinan lain telah dihapus.

## 4. Fokus saat ini: Join to Create

### Sudah

- Inventaris owner/admin membaca konfigurasi PostgreSQL dan daftar channel sementara yang tersimpan. ID pemilik dan token pending tidak dikirim ke browser; respons memakai `no-store`.
- Data hilang, kedaluwarsa, terlalu besar, rusak atau konflik key ditangani secara berbeda; data tersimpan **bukan bukti** channel masih ada di Discord.
- **Cutover penulis bot selesai.** Perintah `/jointocreate`, event `voiceStateUpdate` dan `channelDelete`, serta rekonsiliasi saat startup memakai satu protokol transaksi (`postgresJoinToCreateTransactions.js`) lewat satu runtime (`joinToCreateRuntime.js`). Penulis lama yang menyimpan ulang seluruh objek tanpa kunci sudah dihapus.
- Penulis key/value generik (`set`, `delete`, `increment`, `decrement`) menolak key Join to Create.
- Urutan create: reservasi di database → create di Discord → pendaftaran. Delete: Discord dulu, baru record. Create yang terputus diselesaikan otomatis hanya bila tepat satu channel cocok; bila ragu, tidak ada yang dihapus.
- Rekonsiliasi saat bot menyala: record tanpa channel, channel kosong, pemilik yang sudah pergi, trigger yang hilang, anggota yang menunggu di trigger.
- Tes memakai PostgreSQL lokal dan guild Discord tiruan: 20 anggota masuk bersamaan, penolakan dan timeout Discord, respons COMMIT yang hilang, enam skenario mati di tengah create.
- **Pengaturan trigger di dashboard.** Memakai runtime yang sama dengan perintah slash, dengan login owner/admin, Origin, CSRF, konfirmasi dan `configRevision`. Hanya bidang yang diubah yang dikirim.

### Belum dan risiko yang masih ada

- **Belum pernah dijalankan di Discord sungguhan.** Rate limit, urutan event gateway dan izin yang sebenarnya belum terbukti.
- Antrean operasi hanya ada di dalam satu proses bot. Dua proses pada guild yang sama tidak merusak record, tetapi alurnya belum diuji.
- Channel yang dibuat Discord setelah bot selesai memeriksa, lalu bot mati sebelum jawaban terlambat tiba, tidak terdaftar; cari lewat audit log dengan alasan `Join to Create <token>`.
- Event yang gagal diproses (misalnya database mati) tidak diulang; sisanya baru dibersihkan saat bot menyala lagi.
- Dashboard hanya mengubah pengaturan tersimpan; channel sementara tidak bisa dikelola dari web. Nama channel dan izin bot yang ditampilkan berasal dari cache bot. Pemeriksaan Discord di dashboard hanya snapshot untuk ID tersimpan: **bukan bukti** asal channel, pemilik atau izin.
- Tampilan halaman pengaturan belum dilihat di browser sungguhan.
- SQL langsung dan restore backup tidak menghormati advisory lock.
- Rincian: [`docs/join-to-create-pg.md`](join-to-create-pg.md).

## 5. Penyimpanan, keamanan dan operasional

### PostgreSQL — backend runtime saat ini

**Sudah:** startup gagal tertutup bila PostgreSQL tidak tersedia atau pemeriksaan skema/key tertentu gagal; tidak fallback diam-diam ke RAM. TLS runtime memverifikasi sertifikat dan hostname. `/health` menunjukkan liveness proses; `/ready` memeriksa kesiapan Discord dan query PostgreSQL pada saat itu. Backup `pg_dump` dan restore drill ke database uji terpisah telah diuji lokal.

**Belum:** semua jalur runtime belum sepenuhnya diaudit. Sebagian kode lama dapat menangkap error atau memakai default, dan `/ready` bukan jaminan operasi berikutnya aman. Pemeriksaan skema/key legacy tidak mencakup semua kemungkinan. Backup offsite, retensi, enkripsi dan restore produksi belum diselesaikan atau diuji di hosting pengguna. `pg_restore --list` bukan bukti recovery yang berhasil.

### SQLite — database bawaan

**Sudah:** bot memilih SQLite bila tidak ada koneksi PostgreSQL yang diatur dan membuat berkasnya sendiri (`src/config/database/engine.js`, `src/utils/database/wrapper.js`); `NODE_ENV=production` tidak lagi menuntut nilai PostgreSQL. Penyimpanan to-do, counting, reaction role, server stats, lamaran, Join to Create, giveaway, tiket, level dan reward role, ekonomi, ulang tahun, welcome/goodbye/autorole, warning, akses perintah dan pengaturan server berjalan di SQLite. Suite fitur PostgreSQL dijalankan ulang pada SQLite (`tests/sqlite-feature-suites.test.js`), dan seluruh formulir dashboard memberi status jawaban yang sama pada kedua database.

**Belum:** pemindahan data PostgreSQL ke SQLite (tidak dikerjakan; importer snapshot tetap eksperimen internal); pengujian di hosting sungguhan, dengan Discord sungguhan, di bawah beban, dengan beberapa proses bot pada satu berkas, atau pada penyimpanan jaringan; AFK di SQLite (ditolak adapter, tidak dipakai perintah mana pun); `Dockerfile` kini memakai Node 22 tetapi image-nya belum pernah dibangun dalam pengujian; cadangan SQLite (`npm run backup:db`) dan pemulihannya baru diuji lokal. Perbedaan perilaku dengan PostgreSQL dicatat di [`docs/migrasi-sqlite.md`](migrasi-sqlite.md).

### Aturan operasional penting

1. Sebelum upgrade jalur yang memakai transaksi baru: hentikan instance lama dan penulis lain, backup, audit data/key legacy dan uji restore di target uji terpisah. Penulis SQL langsung, skrip luar, migrasi/restore dan bot lama dapat melewati lock aplikasi.
2. Discord dan database bukan satu transaksi. Jika pengiriman, pembuatan atau commit gagal/tidak diketahui, periksa keduanya sebelum mengulangi; jangan anggap rollback atau retry otomatis aman.
3. Jangan membagikan token bot, URL database, file `.env`, API key, backup, atau data pribadi. Token GitHub yang pernah muncul di percakapan harus dianggap terekspos; **belum ada bukti pencabutannya** dalam dokumentasi ini. Cabut/rotasi melalui penyedia jika belum dilakukan.
4. Login/sesi dashboard, sebagian state musik, sebagian memori AI dan rancangan Server Builder (bukan riwayat bangunannya, yang tersimpan di database) berada di memori proses; restart atau beberapa instance dapat mengubah perilakunya. Review kebutuhan session store dan koordinasi lintas instance sebelum deployment multi-worker.
5. Tes lokal bukan jaminan keamanan, kelengkapan data, izin Discord atau kesiapan produksi.
