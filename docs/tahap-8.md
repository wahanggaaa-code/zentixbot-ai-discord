# Tahap 8 — Integrasi fitur AI (berjalan)

## AI Welcome & Goodbye
AI Welcome terintegrasi pada event anggota bergabung di server `GUILD_ID`; default **nonaktif**. AI Goodbye juga terintegrasi secara terpisah pada event anggota keluar, hanya ke channel (tanpa DM). AI Studio → Welcome & goodbye hanya dapat diatur bot owner (`OWNER_IDS`) yang juga lolos login dan otorisasi dashboard; PATCH dan preview memakai CSRF/Origin. Bisa memilih channel teks server, DM atau keduanya, bahasa, gaya dan template cadangan. Untuk mengaktifkan channel, bot harus memiliki View Channel dan Send Messages. Simpan dahulu sebelum menguji. Tombol preview hanya membuat teks contoh, tidak mengirim pesan Discord, tetapi mungkin memakai kuota dan menimbulkan biaya provider. Preview menggunakan sampel, bukan identitas anggota.

Saat AI Welcome aktif, pesan ini **menggantikan** welcome lama; tidak mengirim dua welcome untuk satu event. Autorole, verification, log join dan counter tetap berjalan; proses AI yang lambat tidak menunda autorole. Penyampaian channel dan DM dilakukan terpisah, sehingga DM tertutup tidak menghalangi channel. Gagal mengirim ke suatu tujuan tidak otomatis dicoba lagi dan tidak mengirim welcome lama untuk menghindari duplikasi. Discord mungkin mengirim ulang event atau ada beberapa proses bot: tidak ada jaminan tepat satu kali. Jangan jalankan beberapa instance tanpa koordinasi.

Jika AI dinonaktifkan, key kosong, batas terlampaui, respons tidak valid, atau provider utama/cadangan gagal, gunakan template cadangan yang disimpan. Respons AI harus mengandung `{user}` dan `{server}` dan tidak boleh memiliki URL, mention langsung atau placeholder lain; filter ini hanya pemeriksaan format, **bukan moderasi konten**. Respons dapat keliru atau tidak pantas; evaluasi sebelum produksi. `{user}` dan `{server}` diisi lokal setelah respons. Ping Discord tidak diizinkan pada pesan AI Welcome atau DM. Template fallback boleh memakai variabel welcome lama; konfigurasi welcome lama (termasuk ping) tetap digunakan ketika AI Welcome nonaktif. Jika database pengaturan AI Welcome gagal dibaca, bot kembali ke welcome lama jika aktif, bukan template AI yang tidak dapat diakses.

### Privasi dan batasan
- Provider hanya menerima instruksi umum, bahasa dan gaya; nama/ID anggota, nama/ID server dan konten pesan **tidak** dimasukkan ke prompt. Nama server dan mention anggota ditambahkan secara lokal setelah respons, termasuk saat template cadangan dipakai. DM opsional menyampaikan nama server kepada anggota dan mungkin tidak diinginkan; owner harus mempertimbangkan kebijakan server.
- Aktivitas join otomatis memakai ID **bot** sebagai identitas per-user dalam penghitung kuota (bukan ID anggota baru). Batas harian bot dan batas server dapat membuat AI jatuh ke template, termasuk untuk banyak anggota bergabung. Permintaan cadangan provider dan percobaan yang gagal dapat menimbulkan biaya; lihat Tahap 7. Preview memakai ID owner untuk kuota. Kuota tidak menjamin batas biaya.
- Pengaturan disimpan di PostgreSQL tabel `cache_data`. Fitur tidak aktif hanya karena mengisi key: fondasi provider Tahap 7 dan AI Welcome masing-masing harus diaktifkan. Data prompt dan hasil tidak dicatat oleh modul ini, tetapi provider punya kebijakan sendiri. Peninjauan kebijakan, retensi database, rate limit, moderasi dan perlindungan abuse tetap penting.

## Activities — trivia dan tebak emoji
Owner dapat memilih jenis permainan, channel teks, durasi 30–300 detik dan bahasa, lalu memulai ronde manual atau menjadwalkan harian/hari kerja/akhir pekan pada WIB, WITA atau WIT. Bot membuat empat pilihan memakai AI atau soal cadangan tetap jika gagal. Jawaban pertama yang benar menutup ronde; satu jawaban per orang. Bot perlu View Channel, Send Messages dan Embed Links. Pertanyaan AI dapat salah; filter struktur bukan verifikasi fakta. Pemenang mendapat poin Activities sesuai nilai owner (0–1000, default 0), terpisah dari wallet ekonomi bot dan tanpa fungsi penukaran. Tombol “Poin saya” menampilkan saldo pribadi. Ronde dan penambahan poin diproses dalam transaksi dengan row lock. Pengujian PostgreSQL 17 lokal menggunakan 100 jawaban benar bersamaan menghasilkan satu pemenang dan satu hadiah; 100 klaim jadwal menghasilkan satu klaim, dan saldo poin invalid diuji rollback. Ini belum membuktikan perilaku Discord, multi-instance lengkap atau seluruh ekonomi. Jadwal diperiksa saat bot online; jadwal yang terlewat tidak dikejar. Slot yang sudah diklaim tidak diulang jika gagal atau ronde lain masih aktif. Jadwal memakai ID bot untuk kuota. Periksa zona waktu dan jam server saat uji akhir.

Status ronde, soal, kunci jawaban, ID channel/pesan dan daftar ID yang telah menjawab tersimpan di PostgreSQL dalam `cache_data`; data ronde terakhir tetap tersimpan sampai diganti. Tab preview live membaca status ronde terbaru dari database saat dimuat atau disegarkan; UI tidak menampilkan kunci selama ronde aktif, dan kedaluwarsa dihitung saat dibaca. Tombol memverifikasi guild, ronde, pesan, waktu, dan peserta menggunakan row lock. Jika bot restart, timer penutupan visual tidak dipulihkan; jawaban tetap ditolak setelah kedaluwarsa dan klik berikutnya dapat menutup tampilan. Jika pengiriman ke Discord error/timeout, hasilnya mungkin tidak pasti: ronde tetap dicadangkan sampai kedaluwarsa dan upaya memulai ronde baru ditolak sementara; periksa channel sebelum mencoba lagi. Jika pengiriman berhasil tetapi penyimpanan ID pesan gagal, periksa Discord sebelum mencoba ulang. Ronde tanpa ID pesan tersimpan tidak dapat menerima jawaban. Kuota dan biaya AI berlaku, dan prompt soal tidak memuat identitas peserta.

### Migrasi transaksi ekonomi (masih berlangsung)
Transfer `/pay` dan `/rob` sekarang memakai transaksi PostgreSQL yang mengunci kedua akun dalam urutan ID dan menyimpan kedua sisi dalam commit yang sama. `/daily`, `/work`, `/beg`, `/mine`, `/fish`, `/deposit`, `/withdraw`, `/gamble`, `/crime`, dan `/slut` juga memproses saldo, cooldown atau item yang terkait dalam satu transaksi. Perintah ini gagal tertutup jika database persisten tidak tersedia. Saldo harus berupa integer aman; akun yang belum dimigrasikan dari key legacy ditolak untuk menghindari pembuatan akun kosong. Hasil commit yang tidak diketahui akibat putus koneksi perlu diperiksa sebelum mencoba ulang. **Ini belum membuat seluruh ekonomi aman dari balapan:** pembelian role premium masih memakai read-modify-write lama dan melakukan tindakan Discord terpisah; setter legacy serta operasi penghapusan/migrasi data juga harus diaudit sebelum hadiah wallet diaktifkan. Pembelian item non-role serta helper penambahan/pengurangan saldo telah dipindah ke transaksi yang sama. Jangan sambungkan hadiah Activities ke wallet sampai semua penulis dimigrasi dan diuji bersama. Mock tidak menggantikan uji konkurensi PostgreSQL nyata; migrasi key harus dijalankan saat bot berhenti, setelah backup.

## Agent & Chat — dasar
Owner dapat mengaktifkan chat channel dan/atau DM. `/aichat mode:channel question:<teks> consent:true` hanya aktif pada channel yang dipilih; jawaban ephemeral. Untuk DM, anggota menjalankan `/aichat mode:dm` di server, lalu membaca pemberitahuan di DM, menekan tombol persetujuan dan mengisi modal. Setiap interaksi DM diperiksa untuk guild utama, pemilik dan keanggotaan server yang diperbarui; mematikan DM menghentikan pemrosesan. Input dan persona dikirim ke provider utama dan mungkin cadangan. Jangan kirim data sensitif; provider dan Discord memiliki kebijakan masing-masing. Memori DM opsional tersimpan sementara di RAM proses, terpisah dari memori channel, dan tidak disediakan untuk admin pada modul ini; ini tidak menjamin privasi absolut. Persona disimpan di PostgreSQL. Di channel, opsi `memory:true` menyetujui penggunaan serta penyimpanan sementara maksimum dua pertukaran teks (masing-masing potongan 350 karakter) untuk akun yang sama; `mode:memory` melihat dan `mode:clear` menghapus. Setiap pertanyaan tetap butuh `consent:true`. Untuk DM, centang memori pada modal; tombol DM memungkinkan pengguna melihat dan menghapus memori DM sendiri. Memori hanya di RAM proses, berlaku 30 menit setelah pertukaran terakhir, dibersihkan berkala (hingga 1 menit setelah kedaluwarsa) atau saat restart; berbeda antar instance. Hanya satu permintaan dengan memori untuk pengguna dan scope yang sama boleh berjalan per proses; permintaan berikutnya ditolak sebelum memanggil provider atau mengunduh lampiran dan dapat dicoba lagi setelah selesai. DM dan channel memiliki scope terpisah; permintaan tanpa memori tidak dibatasi oleh pengaman ini. Pengaman ini tidak berkoordinasi antar-instance. Permintaan yang sedang berjalan mungkin sudah mengirim riwayat ke provider saat penghapusan. Tidak menjamin penghapusan di provider/Discord atau dari dump memori. Jangan kirim rahasia.

Jika owner mengizinkan akses pengetahuan anggota, opsi `knowledge:true` mengirim sampai tiga cuplikan relevan dan pertanyaan ke provider dan dapat mengungkap isinya kepada anggota. Anggap seluruh dokumen tersedia bagi anggota; jangan aktifkan untuk dokumen privat. Kecocokan sederhana tidak menjamin sumber akurat, dan instruksi dalam dokumen bisa memengaruhi respons. Nama sumber hanyalah kandidat. Opsi `image` pada `/aichat` dan lampiran modal DM menerima lampiran Discord PNG/JPEG maksimum 1 MB yang dikirim ke provider, termasuk kemungkinan provider cadangan; perlu model vision yang kompatibel. Validasi hanya memeriksa signature dan batas ukuran, bukan integritas atau moderasi gambar. Perintah dan lampiran Discord bisa terlihat di channel meskipun jawaban ephemeral. Audio opsional di channel atau modal DM menerima OGG, WAV, MP3, M4A, FLAC, atau WebM maksimum 2 MB; owner harus mengaktifkan audio dan mengisi `AI_AUDIO_API_KEY` serta `AI_AUDIO_MODEL` (misalnya `gpt-transcribe`). Dengan `consent:true`, rekaman dikirim ke penyedia transkripsi (OpenAI, atau Groq bila `AI_AUDIO_PROVIDER=groq`); transkrip sampai 1500 karakter diteruskan ke provider chat dan mungkin provider cadangan. Kedua langkah memakai kuota terpisah dan dapat menimbulkan biaya; transkripsi bisa berhasil dan berbiaya walaupun jawaban chat kemudian gagal. Cek dukungan model terbaru di https://developers.openai.com/api/docs/guides/speech-to-text . Ukuran bukan batas durasi atau biaya, dan signature bukan validasi integritas audio. Jangan kirim suara tanpa persetujuan semua pihak terkait. Perintah/lampiran bisa terlihat di channel. Opsi file dapat diaktifkan owner untuk mengirim teks UTF-8 TXT/MD/CSV/JSON dari attachment channel atau modal DM ke provider; maksimal 12.000 byte dan 2.000 karakter, tidak disimpan dalam database oleh modul chat. Dalam satu permintaan pilih hanya satu dari gambar, audio, atau file. PDF/DOCX tidak diterima dari anggota karena parser belum diisolasi sebagai sandbox; owner dapat mengunggahnya melalui Pengetahuan. Owner dapat mengirim panel publik dari dashboard ke channel tersimpan untuk membuka DM; pengiriman ulang membuat panel tambahan. Modal DM memiliki satu lampiran opsional dan persetujuan per pertanyaan; dukungan Discord terhadap modal upload/checkbox harus diuji pada Tahap 9. Lampiran dapat diproses oleh Discord dan provider; DM bukan jaminan privasi absolut.

Owner dapat mengaktifkan agent proaktif: satu icebreaker AI per hari pada jam dan zona WIB/WITA/WIT, di channel yang dipilih. Tidak membaca pesan anggota; persona dikirim ke provider dan output diposting publik tanpa mention. Slot hanya diproses saat bot online dan diklaim sebelum pemrosesan; kesalahan provider atau pengiriman tidak diulang, dan tidak ada jaminan berhasil atau tepat sekali jika Discord menerima pesan tetapi respons gagal. Pakai ID bot untuk kuota. Konten dapat keliru; filter bukan moderasi. Discord harus mendaftarkan ulang command; saat ini jumlah command guild tepat 100 sehingga penambahan command lain perlu konsolidasi.

AI Goodbye memakai prompt perpisahan umum tanpa nama/ID anggota atau server, fallback dan batas keamanan yang sama dengan AI Welcome. Saat aktif ia menggantikan goodbye lama; log dan pembersihan data anggota tetap berjalan, termasuk ketika channel goodbye tidak tersedia.

## AI interaktif di channel (14 November 2026)

Bot menjawab pesan biasa di channel, tanpa perintah. Pengaturannya di dashboard: **AI Studio → Agent & chat → tab "AI interaktif"**, khusus owner bot. Semuanya mati sampai dinyalakan, dan AI harus sudah aktif di **Provider & fallback**. Ini terpisah dari `/aichat`: pengaturan `/aichat` tidak berubah.

| Cara | Kapan bot menulis | Bawaan |
|---|---|---|
| Balas saat di-mention atau di-reply | Anggota me-mention bot atau me-reply pesan bot, di channel chat yang dipilih | Nyala begitu fitur dinyalakan |
| …di semua channel | Sama, tetapi di semua channel yang bisa ditulisi bot | Mati |
| Ikut nimbrung | Pesan biasa di channel chat yang tidak ditujukan kepada siapa pun, dengan peluang 1–100 % per pesan dan jeda 10–3600 detik antara dua kali nimbrung per channel | Mati (20 %, 60 detik) |
| Menyapa saat channel sepi | Channel chat tidak ada pesan selama 10–720 menit, dalam jam aktif, paling banyak 1–24 kali per hari | Mati (30 menit, 08:00–22:00 WIB, 6 kali) |
| Komentar galeri | Setiap kiriman gambar di channel galeri yang dipilih | Mati |
| Baca gambar | Gambar pada pesan yang ditujukan kepada bot ikut dikirim ke model | Mati |

Channel chat paling banyak 10, channel galeri paling banyak 5.

**Yang dikirim ke provider untuk setiap jawaban:** persona, nama bot, nama server dan channel, hari, tanggal dan jam setempat (WIB, WITA atau WIT), sampai 12 pesan terakhir channel itu, dan gambarnya bila "baca gambar" menyala. Pesan anggota diubah menjadi satu baris teks: mention menjadi nama, emoji server menjadi `:nama:`, stiker menjadi `[stiker: nama]`, lampiran menjadi `[gambar]`, `[video]` atau `[file]`. ID Discord tidak dikirim. Nama tampilan anggota dikirim supaya bot bisa menyapa dengan nama; mematikan saklar "Panggil anggota dengan namanya" menggantinya dengan "Anggota 1", "Anggota 2", dan seterusnya.

### Privasi dan batasan

- **Tidak ada persetujuan per pesan.** Begitu sebuah channel dipilih, pesan setiap anggota di channel itu dapat dikirim ke provider AI, juga pesan anggota yang tidak memanggil bot (pesan itu menjadi bagian dari 12 pesan terakhir). Beri tahu anggota, misalnya di topik channel. `/aichat` tetap meminta `consent` per permintaan.
- Bila tidak ada channel chat yang dicentang dan bot hanya membalas saat dipanggil ("…di semua channel"), yang dikirim hanya pesan yang memanggil bot itu sendiri.
- Riwayat percakapan hanya ada di memori proses bot: 12 baris per channel chat, paling lama 2 jam, hilang saat bot restart. Tidak ditulis ke database. Channel galeri dan channel di luar daftar chat tidak diingat sama sekali.
- **Kuota.** Setiap jawaban memakai satu permintaan dari kuota harian anggota yang dijawab dan dari kuota server (Provider & fallback). Sapaan saat sepi memakai kuota atas nama bot. Bila kuota anggota habis, anggota yang memanggil bot diberi tahu paling banyak sekali per jam; selain itu bot diam.
- **Rem.** Paling banyak 1–200 pesan bot per channel per jam (bawaan 30), apa pun pemicunya. Satu anggota dijawab paling cepat setiap 4 detik. Dalam satu channel jawaban ditulis satu per satu dan paling banyak tiga panggilan menunggu; selebihnya tidak dijawab.
- Sapaan saat sepi tidak diulang sebelum ada anggota yang menulis lagi di channel itu. Setelah bot restart, bot bertanya dulu ke Discord siapa penulis pesan terakhir, dan diam bila itu bot sendiri atau bila pesan tidak bisa dibaca. Percobaan yang gagal diulang paling cepat 15 menit kemudian.
- **Gambar** memerlukan model yang bisa membaca gambar. Bila model menolak, kiriman galeri tidak dikomentari (satu peringatan di log), dan anggota yang memanggil bot tetap dijawab tanpa gambar, dengan pesan kepada model agar tidak menebak isinya. PNG atau JPEG sampai 1 MB dibaca apa adanya dari CDN Discord; gambar lain diminta ke proxy media Discord dalam bentuk JPEG yang diperkecil (sisi terpanjang 1024 piksel). Hanya gambar pertama pada sebuah pesan yang dibaca. **Video tidak dibaca**: model hanya tahu bahwa ada video.
- Jawaban bot tidak dapat me-mention siapa pun selain anggota yang dibalasnya; `@everyone` dan `@here` dinetralkan dan tautan undangan Discord dihapus. Isi jawaban tetap buatan model dan dapat keliru atau tidak pantas; tidak ada penyaring isi selain milik provider.
- Bot tidak menjawab bot lain, webhook, pesan sistem, perintah berawalan prefix, atau pesan dari server selain `GUILD_ID`. Channel permainan berhitung tetap ditangani permainan itu; jangan memilihnya sebagai channel chat.
- Anggota dapat mencoba membujuk model lewat pesan (prompt injection). Prompt menyuruh model memperlakukan pesan sebagai obrolan, tetapi itu bukan jaminan. Jangan menaruh rahasia di persona.
- Kegagalan provider tidak ditulis ke channel. Di log muncul satu baris `WARN` per sebab per 10 menit, tanpa isi pesan.

## Pengetahuan dan tools
Owner dapat menyimpan maksimal 10 dokumen UTF-8 `.txt`/`.md`/`.csv`/`.json` (CSV dan JSON sebagai teks biasa; UI maksimum 12.000 byte), atau PDF/DOCX maksimum 1 MB yang diekstrak menjadi teks (PDF maksimum 30 halaman, hasil maksimum 12.000 karakter), di PostgreSQL. File asli tidak disimpan. PDF scan tidak diekstrak sebagai teks biasa: owner dapat memilih OCR satu halaman PDF pada satu waktu (nomor 1–30, berkas maksimal 1 MB), atau OCR gambar PNG/JPEG hingga 1 MB. PDF dirender lokal menjadi PNG maksimal 1536 piksel per sisi dan 1 MB, lalu gambar halaman dikirim ke provider vision setelah konfirmasi owner. Tidak ada OCR otomatis seluruh dokumen; ulangi per halaman. Render dapat gagal atau mengabaikan gambar PDF sangat besar, sehingga teks bisa hilang tanpa peringatan. Render PDF OCR memakai proses anak dengan batas waktu 15 detik, heap JavaScript 128 MB dan satu render bersamaan; memori native tidak dibatasi dan ini bukan sandbox OS. Membutuhkan binary native `@napi-rs/canvas` yang kompatibel dengan hosting. Jangan proses PDF tidak tepercaya tanpa isolasi OS dan batas memori kontainer. Hasil maksimal 5000 karakter ditampilkan untuk ditinjau dan diedit; penyimpanan memerlukan konfirmasi kedua. AI bisa salah, melewatkan atau mengarang teks, mungkin mematuhi instruksi dalam gambar, dan model dengan batas output rendah dapat memotong hasil. Tidak ada indikasi jaminan kelengkapan; periksa sumber. Tata letak dan isi kompleks mungkin hilang. Parser berjalan dalam proses anak terbatas waktu/memori, **bukan sandbox OS**; hanya owner dapat mengunggah, dan jangan memproses file tidak tepercaya di lingkungan produksi tanpa isolasi tambahan. Tampilan daftar hanya metadata; hapus dari database tidak menghapus backup atau data yang telah dikirim ke provider. Jangan unggah rahasia. Uji pengetahuan mencari kata dalam cuplikan dan mengirim hingga tiga cuplikan dengan pertanyaan ke provider setelah konfirmasi. Pencarian leksikal mencocokkan kata utuh dengan potongan bertumpang tindih dan memprioritaskan sumber berbeda; ini bukan pencarian semantik dan dapat melewatkan variasi kata. Nama sumber yang ditampilkan adalah kandidat, bukan bukti jawaban benar. Dokumen dapat berisi prompt injection; filter ini tidak menjamin AI mengabaikan instruksi berbahaya. Akses chat anggota nonaktif secara default dan diaktifkan terpisah oleh owner seperti dijelaskan di atas.

Tools owner menyediakan ringkasan, terjemahan Indonesia/Inggris dan tinjauan klaim dengan konfirmasi. Tinjauan bukan pemeriksaan fakta berbasis sumber. Pencarian web tersedia melalui Brave Search jika `AI_BRAVE_SEARCH_KEY` diatur, atau melalui Tavily jika `AI_SEARCH_PROVIDER=tavily` dan `AI_TAVILY_API_KEY` diatur; hasil kedua penyedia melewati penyaring yang sama (hanya `http`/`https`, tanpa kredensial di URL, paling banyak lima). Mode riset mengirim pertanyaan ke penyedia pencarian itu lalu hingga tiga cuplikan ke provider AI, menampilkan tautan sumber kandidat; ini bukan pembacaan artikel penuh atau verifikasi fakta dan dapat keliru. Dua langkah memakai kuota terpisah serta berpotensi berbiaya. Mode rangkuman tautan mengambil halaman HTTPS publik tanpa redirect, maksimal 128 KB HTML/teks UTF-8, lalu mengirim maksimum 2.500 karakter ke provider. Alamat DNS diperiksa dan koneksi dipin ke alamat publik, tetapi proteksi ini bukan audit keamanan lengkap. URL bertanda tangan atau berisi rahasia jangan digunakan; situs target menerima permintaan. Video YouTube memerlukan transkrip yang ditempel; tidak ada pengambilan transkrip otomatis. Dokumentasi: https://api-dashboard.search.brave.com/documentation/services/web-search . Data yang dikirim diproses provider dan fallback; hasil bisa salah. Tidak ada penyimpanan input dan hasil di modul tools.

## Gambar
Penyedia gambar dipilih dengan `AI_IMAGE_PROVIDER`: `openai` (bawaan), `cloudflare` atau `pollinations`; rincian dan batas dua alternatif itu ada di [`docs/hosting.md`](hosting.md). Cloudflare dan Pollinations hanya membuat gambar dan mengembalikan JPEG; Cloudflare tidak meneruskan pilihan ukuran dan Pollinations memperkecilnya ke batas 768 × 768; keterangan di bawah ini berlaku untuk OpenAI. Buat dan edit melalui OpenAI Images API jika owner mengisi `AI_IMAGE_API_KEY` dan `AI_IMAGE_MODEL` di environment server dan mengaktifkan fondasi AI. Model harus mendukung endpoint terkait; konfirmasi model dan akses pada dokumentasi OpenAI sebelum uji langsung: https://developers.openai.com/api/reference/resources/images/ . Satu gambar PNG per permintaan dengan pilihan 1024×1024, 1536×1024 atau 1024×1536 sesuai dukungan model; gaya dipilih sebagai instruksi prompt, bukan jaminan hasil; edit menerima input PNG maksimum 1,5 MB dan dimensi maksimum 2048. Prompt dan input dikirim ke OpenAI setelah konfirmasi; hasil PNG dikembalikan ke browser tanpa disimpan bot. Batas ukuran dan header bukan validasi keamanan PNG menyeluruh. Tidak ada fallback gambar, penyimpanan hasil oleh bot atau dukungan file input lain. Kuota AI bersama dihitung sebelum panggilan; biaya dapat berbeda dari teks. Timeout 120 detik, satu permintaan gambar per proses; ini bukan batas biaya.

## Server Builder
Tersedia di dashboard: **AI Studio → Server Builder**, khusus owner bot (`OWNER_IDS`) dan hanya untuk server utama. Tidak ada perintah slash untuk builder: bot sudah memakai seluruh 100 perintah slash yang diterima Discord per server, sehingga perintah baru akan menggeser perintah lama (keputusan pemilik bot, 14 November 2026).

**Membuat rancangan.** Ada dua cara, dan tidak satu pun membuat sesuatu di Discord sebelum ditinjau dan dikonfirmasi:

- **Tema siap pakai** ("Pakai tema"): 15 tema berbahasa Indonesia (gaming, komunitas, aesthetic, belajar, musik, seni, teknologi, crypto, anime, roleplay, bisnis, coding, kesehatan, keluarga, startup). Tidak memakai AI, tidak memakai kuota, dan hanya berisi channel teks dan suara sehingga berjalan di server tanpa fitur Komunitas.
- **Deskripsi untuk AI** ("Rancang dengan AI"): deskripsi dikirim ke provider AI. Bila AI mati, kuota habis, provider gagal, atau jawabannya bukan rancangan yang sah, builder memakai tema yang paling dekat dengan kata-kata di deskripsi (bila tidak ada yang cocok: tema komunitas) dan mengatakan alasannya. Server, anggota atau persetujuan yang salah tetap ditolak, tidak diganti tema.

Besar rancangan AI mengikuti **batas output** di *Provider & fallback*, karena jawaban yang terpotong tidak bisa dipakai: pada 256 token (bawaan) AI diminta paling banyak 6 channel dalam 2 kategori dan 2 role; pada 512 token 14 channel, 4 kategori, 4 role; pada 1024 token 31 channel, 8 kategori, 10 role. Mulai 1200 token AI juga diminta menulis topik tiap channel, yang memakan tempat: 18 channel pada 1200 token, 32 channel, 8 kategori dan 10 role pada 2048 token. Naikkan batas output bila ingin rancangan AI yang lebih besar; tema tidak terpengaruh.

**Isi rancangan.** Paling banyak 8 kategori, 15 channel per kategori, 40 channel seluruhnya dan 12 role; nama paling panjang 50 karakter, topik 200. Nama boleh memakai emoji. Tipe channel: `text`, `voice`, serta `forum`, `news` dan `stage` yang hanya diterima bila server mempunyai fitur Komunitas Discord. Role boleh diberi warna (`#RRGGBB`) dan selalu dibuat tanpa izin khusus, tidak dapat di-mention dan tidak ditampilkan terpisah. Kunci lain, misalnya izin, ditolak. Channel mewarisi izin kategori/server dan mungkin terlihat oleh semua anggota.

**Meninjau dan menerapkan.** Dashboard menampilkan rancangan sebagai susunan yang bisa dibaca (kategori, channel dengan tipenya, role dengan warnanya); JSON-nya dapat disunting dan divalidasi ulang. Rancangan terikat pada pembuatnya, berlaku 5 menit, sekali pakai, dan satu orang hanya mempunyai satu rancangan yang menunggu; rancangan yang masih menunggu ditampilkan lagi setelah halaman dimuat ulang. Penyuntingan tidak memperpanjang masa berlaku. Penerapan ditolak bila ada nama yang sudah dipakai di server, bila batas channel/role Discord akan terlampaui, atau bila bot tidak mempunyai izin Kelola Channel/Kelola Role.

**Riwayat dan bongkar.** Setiap penerapan dicatat di database beserta ID Discord setiap objek yang benar-benar dibuat, juga bila penerapan berhenti di tengah jalan; 20 bangunan terakhir disimpan per server. Bila riwayat tidak dapat dibaca, penerapan ditolak. **Bongkar** (tab "Riwayat & bongkar") menghapus objek bangunan **terakhir** berdasarkan ID itu saja, bukan berdasarkan nama: objek yang sudah diganti namanya tetap terhapus, objek lain yang bernama sama tidak disentuh. Urutannya channel, lalu kategori, lalu role. Sebelum menghapus, builder menampilkan setiap objek dan keadaannya (akan dihapus, sudah tidak ada, dilewati) dan meminta kalimat `BONGKAR <jumlah>` diketik; bila keadaan server berubah setelah tinjauan, permintaan ditolak dan harus ditinjau ulang. Yang dilewati: channel sistem server, kategori yang masih berisi channel yang bukan bagian bangunan itu, dan role yang berada di atas role bot atau dikelola integrasi. Objek yang dilewati atau gagal dihapus tetap tercatat supaya bisa dicoba lagi. "Lepas dari riwayat" hanya membuang catatan bangunan terakhir tanpa menghapus apa pun.

**Bongkar bersifat permanen:** channel dihapus beserta seluruh pesannya dan role dilepas dari semua anggota; bot tidak dapat memulihkannya. Tinjauan memberi tanda bila channel sudah berisi pesan, ruang suara sedang dipakai, atau izin role sudah diubah, tetapi tidak menghitung pesan atau anggota.

Batas yang perlu diketahui: Discord tidak menyediakan transaksi, jadi bila terjadi error/timeout sebagian objek mungkin sudah dibuat atau dihapus; periksa daftar hasil dan server sebelum tindakan berikut. Objek yang dibuat Discord tetapi jawabannya tidak pernah tiba tidak tercatat dan tidak ikut dibongkar. Rancangan dan tinjauan hanya di memori dan hilang saat restart (riwayat tidak). Kunci per server hanya berlaku dalam satu proses bot. Bangunan yang dibuat sebelum pembaruan ini tidak mempunyai catatan. Seluruh alur ini diuji dengan Discord tiruan; pembuatan dan penghapusan belum pernah dijalankan pada Discord nyata. Coba dulu dengan satu tema di server uji.

Operasi manual terpisah memungkinkan owner meninjau lalu mengganti nama atau menghapus satu channel teks/suara/kategori atau role, dan mengatur izin dasar role dari daftar aman terbatas. Ini tidak mengubah permission overwrite channel; izin efektif bisa berbeda. Role `@everyone`, role managed, role yang tidak dapat dikelola bot, atau role dengan izin di luar daftar aman ditolak; channel sistem dan kategori yang masih berisi channel juga ditolak. Pilih target dengan ID, tinjau keadaan saat itu, lalu ketik ID untuk perubahan atau `HAPUS <ID>` untuk penghapusan dan konfirmasi lagi. **Hapus bersifat permanen:** pesan, pengaturan dan penetapan role bisa hilang; bot tidak bisa memulihkannya. Jangan gunakan penghapusan jika data masih diperlukan.

Rollback manual satu kali hanya tersedia selama lima menit untuk rename dan perubahan izin dasar role yang sukses, jika field yang diperiksa belum berubah; penghapusan manual tidak dapat dibatalkan, dan ini terpisah dari Bongkar di atas. Tinjauan dan rollback hilang saat restart, dan perbedaan lain (seperti pesan baru, anggota role, overwrite channel, atau perubahan tepat setelah pemeriksaan) tidak seluruhnya terdeteksi. Discord tidak menyediakan transaksi atomik untuk rangkaian ini; jika timeout, hasil tidak pasti dan pemilik harus memeriksa Discord. Mutex hanya per proses dan terpisah dari proses bot lain. Tindakan manual tidak memakai AI dan tidak berjalan sampai owner mengonfirmasi. Belum diuji pada Discord nyata.

### Tambahan: sopan santun, nama bot, tindak lanjut dan alat

Delapan pengaturan baru di tab yang sama, semuanya mati sampai dinyalakan. Pengaturan yang disimpan sebelumnya tetap terbaca; kunci baru dianggap mati.

| Saklar | Yang berubah |
|---|---|
| Etika anti-nimbrung | "Ikut nimbrung" tidak menyela bila anggota lain menulis di channel itu dalam 90 detik terakhir, dan melewati pesan yang tampak seperti perintah bot lain (`!play`, `.help`), pesan yang hanya berisi tautan, dan pesan tanpa kata (emoji, stiker, angka). Tidak berpengaruh saat bot dipanggil. |
| Jawab saat namanya disebut | Menyebut nama bot sebagai kata utuh dihitung sebagai memanggil, tanpa @mention. Yang dikenali: sampai 5 nama panggilan (2–24 karakter) yang diisi di dashboard; bila daftar itu kosong, username bot dan nama tampilannya di server. "Zen" tidak cocok dengan "zenith". Pesan yang me-reply atau me-mention orang lain tidak dihitung. |
| Obrolan lanjutan | Setelah bot menjawab seorang anggota, 2 pesan berikutnya dari anggota itu di channel yang sama dalam 30–300 detik (bawaan 90) dijawab tanpa mention. Berakhir begitu anggota lain menulis, waktunya habis, atau pesan itu ditujukan kepada orang lain. |

Bila alat gagal karena sebab yang bisa dijelaskan (halaman tidak bisa dibuka, pencarian tanpa hasil, obrolan terlalu sedikit), bot membalas dengan alasannya; kuota habis ditangani seperti jawaban biasa.

### FAQ dan cache jawaban

- **FAQ.** Sampai 25 entri; pertanyaan 3–150 karakter, jawaban sampai 800. Bila anggota memanggil bot (AI interaktif) dengan pertanyaan yang cocok, bot menulis jawaban itu apa adanya: tidak ada permintaan AI dan kuota tidak berkurang.
- **Pencocokan** memakai kata penting, bukan AI: huruf besar, tanda baca, kata pengisi ("gimana", "sih", "dong") dan akhiran `-nya`/`-kah`/`-lah` diabaikan. Minimal dua kata penting harus sama, dan minimal 60 % kata penting entri harus ada di pesan. Ini bukan pencarian makna: "cara verifikasi" tidak cocok dengan entri "cara dapat role member". Tulis pertanyaan dengan kata yang dipakai anggota, dan buat dua entri bila ada dua cara bertanya.
- **Jawab otomatis** (saklar terpisah, dengan daftar channel): di channel yang dicentang, pertanyaan yang cocok dijawab tanpa bot dipanggil. Syaratnya lebih ketat: pesan harus tampak seperti pertanyaan (tanda tanya atau kata tanya) dan minimal 80 % kata penting entri harus ada. Entri yang sama tidak diulang di channel yang sama dalam 2 menit. Pesan yang me-reply atau me-mention orang lain dilewati.
- Jawaban FAQ tidak dapat me-mention siapa pun, juga bila teksnya memuat `@everyone`.
- **Cache jawaban.** Jawaban AI untuk pesan teks yang memanggil bot diingat 1–120 menit (bawaan 15). Pertanyaan yang sama (setelah huruf besar dan tanda baca disamakan) dari siapa pun di server mendapat jawaban yang sama tanpa permintaan AI. Hanya di memori proses, paling banyak 300 jawaban, hilang saat restart. Pesan dengan lampiran, pesan kurang dari tiga kata, reply ke pesan bot dan pesan tindak lanjut tidak di-cache. Begitu pula pertanyaan tentang diri penanya atau tentang obrolan sebelumnya (mengandung "aku", "saya", "gue", "namaku", "my", "tadi", "barusan", "begitu" dan sejenisnya), dan jawaban yang menyebut nama penanya: tanpa itu "siapa nama aku?" dari anggota kedua akan dijawab dengan nama anggota pertama. Saringan ini berbasis daftar kata, bukan makna. Akibatnya: jawaban tidak mengikuti konteks obrolan yang berubah dalam menit-menit itu; matikan bila itu mengganggu.

### Menu pesan

Empat perintah menu pesan (klik kanan atau tekan lama sebuah pesan → **Apps**). Setiap entri punya saklar sendiri; hanya yang menyala yang didaftarkan ke Discord. Ini bukan perintah slash dan tidak mengurangi batas 100 perintah slash; Discord memberi batas terpisah, 5 perintah menu pesan per server.

- Jawabannya hanya terlihat oleh anggota yang mengklik (ephemeral) dan memakai kuota harian anggota itu.
- **Terjemahkan** menerjemahkan ke bahasa yang dipilih di dashboard (Indonesia, Inggris, Jepang, Korea, Mandarin, Arab).
- **Cek fakta** membandingkan pesan dengan 3 cuplikan pencarian web dan menyebut sumbernya. Tanpa kunci pencarian, jawaban diberi catatan "Tanpa pencarian web: ini tinjauan AI, bukan verifikasi." Dengan pencarian pun yang dibaca hanya cuplikan, bukan artikel lengkap.
- **Rangkum dari pesan ini** merangkum sampai 150 pesan yang ditulis setelah pesan yang diklik.
- Menyimpan perubahan saklar mendaftarkan ulang perintah ke Discord saat itu juga. Bila pendaftaran gagal, pengaturan tetap tersimpan dan halaman meminta bot di-restart. Discord dapat memerlukan beberapa menit, atau aplikasi Discord perlu dibuka ulang, sebelum menu berubah.
- Siapa pun yang dapat melihat pesan dapat memakai menu itu. Membatasinya per role atau channel dilakukan di **Server Settings → Integrations** Discord, bukan di dashboard ini.

### Rangkuman obrolan

Dipakai oleh "Rangkum obrolan yang tertinggal" (AI interaktif) dan "Rangkum dari pesan ini" (menu). Bot membaca 25–150 pesan terakhir lewat API Discord (memerlukan **Read Message History**), membuang pesan bot dan pesan tanpa teks, memotong tiap pesan pada 220 karakter, dan mengirim paling banyak sekitar 3.200 karakter transkrip, yang terbaru didahulukan. Pada channel yang ramai, 150 pesan panjang tidak muat semua: bagian yang lebih lama terbuang tanpa pemberitahuan. Hasil diingat 30 menit per channel dan jumlah pesan; permintaan kedua dalam waktu itu tidak memakai kuota dan diberi catatan umurnya. Kurang dari 5 pesan anggota: bot menjawab "Belum cukup obrolan untuk dirangkum."

### Koran pagi

Setiap menit bot memeriksa apakah jam kirim (HH:MM, WIB/WITA/WIT) sudah lewat. Edisi dikirim sekali per hari, teks yang sama ke setiap channel yang dicentang. Bila bot mati pada jam itu, edisi tetap dikirim asalkan bot hidup lagi dalam 60 menit; lebih dari itu, edisi hari itu hilang.

- **Berita** berasal dari satu pencarian web (topik dari dashboard, atau berita Indonesia umum) dan dirangkum dari 4 cuplikan teratas, dengan tautan sumber. Memerlukan kunci pencarian. Tanpa kunci: bila "fakta" menyala, hanya fakta yang dikirim; bila hanya "berita" yang menyala, tidak ada yang dikirim dan log memuat satu baris `AI digest: skipped (…)`.
- **Fakta hari ini** ditulis model tanpa sumber dan dapat keliru.
- Penanda "sudah dikirim" ditulis ke database sebelum AI dipanggil, sehingga restart tidak mengirim dua kali dan kegagalan tidak memakai kuota berulang-ulang. Akibatnya: bila provider gagal atau bot tidak bisa menulis pada menit itu, edisi hari itu hilang dan tidak dicoba lagi; log memuat satu baris `AI digest: skipped (…)`. Channel yang menolak dilewati, channel lain tetap menerima.
- **Kirim tes** mengirim edisi sekarang ke channel yang tersimpan, memakai satu permintaan AI, dan tidak menghabiskan edisi terjadwal hari itu.

### Sapaan multibahasa

Menambah isi pesan AI Welcome dan AI Goodbye yang sudah ada; fitur itu sendiri tetap diatur di ruang **Welcome & Goodbye** dan harus menyala.

- **Sapaan bahasa lain:** satu baris di atas pesan, dipilih acak dari daftar tetap di kode (46 sapaan selamat datang, 25 sapaan perpisahan), dengan nama bahasa, arti, dan cara baca untuk aksara non-Latin. Contoh: `**Yōkoso!** (ようこそ · bahasa Jepang, artinya "selamat datang")`. Daftar ini ditulis tangan dan belum diperiksa penutur asli.
- **Lama keanggotaan:** pada perpisahan, satu baris kecil "Bersama kami selama 3 bulan." dari tanggal bergabung yang dicatat Discord. Bila Discord tidak memberi tanggal itu (anggota tidak ada di cache), baris ini tidak ditulis.

### Terjemahan otomatis

Di channel yang dicentang, pesan yang tampaknya bukan dalam bahasa tujuan dibalas dengan `🌐` dan terjemahannya.

- **Setiap pesan yang lolos saringan dikirim ke provider AI, tanpa persetujuan per pesan.** Beri tahu anggota channel itu.
- Saringan sebelum AI, tanpa biaya: pesan bot, perintah, pesan dengan kurang dari 8 huruf, tautan dan emoji saja, dan pesan yang menurut tebakan kasar sudah berbahasa tujuan. Tebakan itu berdasarkan aksara, daftar kata sehari-hari (termasuk singkatan dan bahasa gaul seperti "yg", "udh", "anjir", "mabar"), bentuk kata Indonesia ("ngakak", "kucingnya") dan tawa ("wkwk", "haha") yang diabaikan; ia salah pada kalimat campuran dan bahasa yang berkerabat (Melayu dianggap Indonesia). Bahasa daerah (Sunda, Jawa) tidak dikenali sebagai Indonesia dan diteruskan ke AI. Bila model menilai pesan sudah berbahasa tujuan, tidak ada balasan, tetapi satu permintaan AI sudah terpakai.
- Rem: 1–120 permintaan AI per channel per jam (bawaan 30), satu anggota paling cepat setiap 3 detik, teks dipotong pada 1.000 karakter. Yang dihitung adalah setiap permintaan yang dijawab provider, juga yang berakhir tanpa balasan, serta terjemahan yang diambil dari ingatan; dengan begitu kuota anggota tidak terkuras diam-diam di channel yang ramai. Teks yang sama diingat 24 jam di memori.
- Memakai kuota harian anggota yang menulis pesan. Bila kuotanya habis, pesan anggota itu tidak diterjemahkan dan tidak ada pemberitahuan.
- FAQ jawab otomatis didahulukan: satu pesan mendapat paling banyak satu balasan. Pesan yang sudah dijawab AI interaktif tidak diterjemahkan.

### Laporan pemakaian

Bila menyala, setiap permintaan AI yang dijawab provider dicatat: tanggal, fitur pemanggil, ID anggota, dan jumlah token bila provider melaporkannya. Isi pesan tidak dicatat. Jawaban dari FAQ dan cache dihitung terpisah sebagai "dijawab tanpa AI".

- Disimpan per hari di database selama 45 hari; laporan menampilkan 7, 14 atau 30 hari terakhir, dengan lima anggota paling aktif. Hari dihitung dalam UTC: satu "hari" di laporan berganti pukul 07.00 WIB.
- Permintaan yang gagal di semua provider tidak dicatat, walaupun kuota hariannya terpakai. Angka laporan karena itu bisa lebih kecil daripada kuota yang terpakai.
- Pembuatan gambar, speech-to-text dan pencarian web tidak lewat lapisan chat dan tidak masuk laporan.
- Jumlah token adalah angka provider; provider yang tidak melaporkannya dihitung 0. Laporan tidak menghitung biaya.
- Tidak ada pencatatan selama saklarnya mati, dan mematikannya tidak menghapus catatan yang ada.

Pengujian kompatibilitas hanya mencakup contoh skema guild, ekonomi, dan input command; perilaku error dan default optional Zod v4 dapat berbeda, jadi verifikasi seluruh jalur pada Tahap 9 sebelum produksi.

### Integritas penyimpanan pengetahuan

Daftar dokumen yang sudah ada kini divalidasi sebelum dibaca atau diubah; record PostgreSQL yang berbentuk tidak valid, berisi ID ganda, melebihi batas, atau bernilai JSON null ditolak tanpa menimpa data. Pemeriksaan tidak membuktikan isi dokumen benar atau aman. Tes pada PostgreSQL lokal menjalankan 15 unggahan bersamaan: 10 tersimpan dan 5 ditolak oleh batas; penghapusan dan penolakan data rusak juga diuji. SQLite tetap eksperimental dan representasi null-versus-key-tidak-ada belum dibuktikan secara menyeluruh. Uji provider/Discord/Wispbyte masih diperlukan.

Pengaturan welcome/goodbye lama untuk edit menolak pembacaan PostgreSQL yang gagal dan tidak mengklaim sukses jika penulisan ditolak. Update parsial PostgreSQL memakai row lock; penyimpanan penuh memeriksa snapshot agar tidak menimpa perubahan terbaru. Ini berbeda dari pengaturan AI Welcome di `cache_data`. Service bot dan dua jalur dashboard PostgreSQL yang diuji kini memeriksa konflik autorole/verification/auto-verify dalam transaksi dengan kunci bersama; penulis lain atau SQL langsung masih dapat melewatinya. Event join/leave lama masih memakai fallback default ketika pembacaan gagal, dan perilaku langsung di Discord belum diuji. Lihat [`docs/postgresql.md`](postgresql.md).
