# Tahap 8 — Integrasi fitur AI (berjalan)

## AI Welcome & Goodbye
AI Welcome terintegrasi pada event anggota bergabung di server `GUILD_ID`; default **nonaktif**. AI Goodbye juga terintegrasi secara terpisah pada event anggota keluar, hanya ke channel (tanpa DM). AI Studio → Welcome & goodbye hanya dapat diatur bot owner (`OWNER_IDS`) yang juga lolos login dan otorisasi dashboard; PATCH dan preview memakai CSRF/Origin. Bisa memilih channel teks server, DM atau keduanya, bahasa, gaya dan template cadangan. Untuk mengaktifkan channel, bot harus memiliki View Channel dan Send Messages. Simpan dahulu sebelum menguji. Tombol preview hanya membuat teks contoh, tidak mengirim pesan Discord, tetapi mungkin memakai kuota dan menimbulkan biaya provider. Preview menggunakan sampel, bukan identitas anggota.

Saat AI Welcome aktif, pesan ini **menggantikan** welcome lama; tidak mengirim dua welcome untuk satu event. Autorole, verification, log join dan counter tetap berjalan; proses AI yang lambat tidak menunda autorole. Penyampaian channel dan DM dilakukan terpisah, sehingga DM tertutup tidak menghalangi channel. Gagal mengirim ke suatu tujuan tidak otomatis dicoba lagi dan tidak mengirim welcome lama untuk menghindari duplikasi. Discord mungkin mengirim ulang event atau ada beberapa proses bot: tidak ada jaminan tepat satu kali. Jangan jalankan beberapa instance tanpa koordinasi.

Jika AI dinonaktifkan, key kosong, batas terlampaui, respons tidak valid, atau provider utama/cadangan gagal, gunakan template cadangan yang disimpan. Respons AI harus mengandung `{user}` dan `{server}` dan tidak boleh memiliki URL, mention langsung atau placeholder lain; filter ini hanya pemeriksaan format, **bukan moderasi konten**. Respons dapat keliru atau tidak pantas; evaluasi sebelum produksi. `{user}` dan `{server}` diisi lokal setelah respons. Ping Discord tidak diizinkan pada pesan AI Welcome atau DM. Template fallback boleh memakai variabel welcome lama; konfigurasi welcome lama (termasuk ping) tetap digunakan ketika AI Welcome nonaktif. Jika database pengaturan AI Welcome gagal dibaca, bot kembali ke welcome lama jika aktif, bukan template AI yang tidak dapat diakses.

### Privasi dan batasan
- Provider hanya menerima instruksi umum, bahasa dan gaya; nama/ID anggota, nama/ID server dan konten pesan **tidak** dimasukkan ke prompt. Nama server dan mention anggota ditambahkan secara lokal setelah respons, termasuk saat template cadangan dipakai. DM opsional menyampaikan nama server kepada anggota dan mungkin tidak diinginkan; owner harus mempertimbangkan kebijakan server.
- Aktivitas join otomatis memakai ID **bot** sebagai identitas per-user dalam penghitung kuota (bukan ID anggota baru). Batas harian bot dan batas server dapat membuat AI jatuh ke template, termasuk untuk banyak anggota bergabung. Permintaan cadangan provider dan percobaan yang gagal dapat menimbulkan biaya; lihat Tahap 7. Preview memakai ID owner untuk kuota. Kuota tidak menjamin batas biaya.
- Pengaturan disimpan di PostgreSQL tabel `cache_data`. Fitur tidak aktif hanya karena mengisi key: fondasi provider Tahap 7 dan AI Welcome masing-masing harus diaktifkan. Data prompt dan hasil tidak dicatat oleh modul ini, tetapi provider punya kebijakan sendiri. Peninjauan kebijakan, retensi database, rate limit, moderasi dan perlindungan abuse tetap penting.

## Activities — trivia dan tebak emoji
Owner dapat memilih jenis permainan, channel teks, durasi 30–300 detik dan bahasa, lalu memulai ronde manual atau menjadwalkan harian/hari kerja/akhir pekan pada WIB, WITA atau WIT. Bot membuat empat pilihan memakai AI atau soal cadangan tetap jika gagal. Jawaban pertama yang benar menutup ronde; satu jawaban per orang. Bot perlu View Channel, Send Messages dan Embed Links. Pertanyaan AI dapat salah; filter struktur bukan verifikasi fakta. Pemenang mendapat poin Activities sesuai nilai owner (0–1000, default 0), terpisah dari wallet ekonomi bot dan tanpa fungsi penukaran. Tombol “Poin saya” menampilkan saldo pribadi. Ronde dan penambahan poin diproses dalam transaksi dengan row lock; tetap perlu uji konkurensi PostgreSQL nyata. Jadwal diperiksa saat bot online; jadwal yang terlewat tidak dikejar. Slot yang sudah diklaim tidak diulang jika gagal atau ronde lain masih aktif. Jadwal memakai ID bot untuk kuota. Periksa zona waktu dan jam server saat uji akhir.

Status ronde, soal, kunci jawaban, ID channel/pesan dan daftar ID yang telah menjawab tersimpan di PostgreSQL dalam `cache_data`; data ronde terakhir tetap tersimpan sampai diganti. UI tidak menampilkan kunci selama ronde aktif. Tombol memverifikasi guild, ronde, pesan, waktu, dan peserta menggunakan row lock. Jika bot restart, timer penutupan visual tidak dipulihkan; jawaban tetap ditolak setelah kedaluwarsa dan klik berikutnya dapat menutup tampilan. Bila pengiriman berhasil tetapi penyimpanan ID pesan gagal, periksa Discord sebelum mencoba ulang. Kuota dan biaya AI berlaku, dan prompt soal tidak memuat identitas peserta.

## Agent & Chat — dasar
Owner dapat mengaktifkan chat channel dan/atau DM. `/aichat mode:channel question:<teks> consent:true` hanya aktif pada channel yang dipilih; jawaban ephemeral. Untuk DM, anggota menjalankan `/aichat mode:dm` di server, lalu membaca pemberitahuan di DM, menekan tombol persetujuan dan mengisi modal. Setiap interaksi DM diperiksa untuk guild utama, pemilik dan keanggotaan server yang diperbarui; mematikan DM menghentikan pemrosesan. Input dan persona dikirim ke provider utama dan mungkin cadangan. Jangan kirim data sensitif; provider dan Discord memiliki kebijakan masing-masing. Memori DM opsional tersimpan sementara di RAM proses, terpisah dari memori channel, dan tidak disediakan untuk admin pada modul ini; ini tidak menjamin privasi absolut. Persona disimpan di PostgreSQL. Di channel, opsi `memory:true` menyetujui penggunaan serta penyimpanan sementara maksimum dua pertukaran teks (masing-masing potongan 350 karakter) untuk akun yang sama; `mode:memory` melihat dan `mode:clear` menghapus. Setiap pertanyaan tetap butuh `consent:true`. Untuk DM, centang memori pada modal; tombol DM memungkinkan pengguna melihat dan menghapus memori DM sendiri. Memori hanya di RAM proses, berlaku 30 menit setelah pertukaran terakhir, dibersihkan berkala (hingga 1 menit setelah kedaluwarsa) atau saat restart; berbeda antar instance. Permintaan yang sedang berjalan mungkin sudah mengirim riwayat ke provider saat penghapusan. Tidak menjamin penghapusan di provider/Discord atau dari dump memori. Jangan kirim rahasia.

Jika owner mengizinkan akses pengetahuan anggota, opsi `knowledge:true` mengirim sampai tiga cuplikan relevan dan pertanyaan ke provider dan dapat mengungkap isinya kepada anggota. Anggap seluruh dokumen tersedia bagi anggota; jangan aktifkan untuk dokumen privat. Kecocokan sederhana tidak menjamin sumber akurat, dan instruksi dalam dokumen bisa memengaruhi respons. Nama sumber hanyalah kandidat. Opsi `image` pada `/aichat` dan lampiran modal DM menerima lampiran Discord PNG/JPEG maksimum 1 MB yang dikirim ke provider, termasuk kemungkinan provider cadangan; perlu model vision yang kompatibel. Validasi hanya memeriksa signature dan batas ukuran, bukan integritas atau moderasi gambar. Perintah dan lampiran Discord bisa terlihat di channel meskipun jawaban ephemeral. Audio opsional di channel atau modal DM menerima OGG, WAV, MP3, M4A, FLAC, atau WebM maksimum 2 MB; owner harus mengaktifkan audio dan mengisi `AI_AUDIO_API_KEY` serta `AI_AUDIO_MODEL` (misalnya `gpt-transcribe`). Dengan `consent:true`, rekaman dikirim ke OpenAI untuk transkripsi; transkrip sampai 1500 karakter diteruskan ke provider chat dan mungkin provider cadangan. Kedua langkah memakai kuota terpisah dan dapat menimbulkan biaya; transkripsi bisa berhasil dan berbiaya walaupun jawaban chat kemudian gagal. Cek dukungan model terbaru di https://developers.openai.com/api/docs/guides/speech-to-text . Ukuran bukan batas durasi atau biaya, dan signature bukan validasi integritas audio. Jangan kirim suara tanpa persetujuan semua pihak terkait. Perintah/lampiran bisa terlihat di channel. Opsi file dapat diaktifkan owner untuk mengirim teks UTF-8 TXT/MD/CSV/JSON dari attachment channel atau modal DM ke provider; maksimal 12.000 byte dan 2.000 karakter, tidak disimpan dalam database oleh modul chat. Dalam satu permintaan pilih hanya satu dari gambar, audio, atau file. PDF/DOCX tidak diterima dari anggota karena parser belum diisolasi sebagai sandbox; owner dapat mengunggahnya melalui Pengetahuan. Owner dapat mengirim panel publik dari dashboard ke channel tersimpan untuk membuka DM; pengiriman ulang membuat panel tambahan. Modal DM memiliki satu lampiran opsional dan persetujuan per pertanyaan; dukungan Discord terhadap modal upload/checkbox harus diuji pada Tahap 9. Lampiran dapat diproses oleh Discord dan provider; DM bukan jaminan privasi absolut.

Owner dapat mengaktifkan agent proaktif: satu icebreaker AI per hari pada jam dan zona WIB/WITA/WIT, di channel yang dipilih. Tidak membaca pesan anggota; persona dikirim ke provider dan output diposting publik tanpa mention. Slot hanya diproses saat bot online dan diklaim sebelum pemrosesan; kesalahan provider atau pengiriman tidak diulang, dan tidak ada jaminan berhasil atau tepat sekali jika Discord menerima pesan tetapi respons gagal. Pakai ID bot untuk kuota. Konten dapat keliru; filter bukan moderasi. Discord harus mendaftarkan ulang command; saat ini jumlah command guild tepat 100 sehingga penambahan command lain perlu konsolidasi.

AI Goodbye memakai prompt perpisahan umum tanpa nama/ID anggota atau server, fallback dan batas keamanan yang sama dengan AI Welcome. Saat aktif ia menggantikan goodbye lama; log dan pembersihan data anggota tetap berjalan, termasuk ketika channel goodbye tidak tersedia.

## Pengetahuan dan tools
Owner dapat menyimpan maksimal 10 dokumen UTF-8 `.txt`/`.md`/`.csv`/`.json` (CSV dan JSON sebagai teks biasa; UI maksimum 12.000 byte), atau PDF/DOCX maksimum 1 MB yang diekstrak menjadi teks (PDF maksimum 30 halaman, hasil maksimum 12.000 karakter), di PostgreSQL. File asli tidak disimpan. PDF scan tidak diekstrak otomatis: konversi halaman secara terpisah menjadi gambar PNG/JPEG terlebih dahulu. OCR gambar sampai 1 MB tersedia lewat model vision fondasi setelah owner mengonfirmasi pengiriman ke provider. Hasil maksimal 5000 karakter ditampilkan untuk ditinjau dan diedit; penyimpanan memerlukan konfirmasi kedua. AI bisa salah, melewatkan atau mengarang teks, mungkin mematuhi instruksi dalam gambar, dan model dengan batas output rendah dapat memotong hasil. Tidak ada indikasi jaminan kelengkapan; periksa sumber. Tata letak dan isi kompleks mungkin hilang. Parser berjalan dalam proses anak terbatas waktu/memori, **bukan sandbox OS**; hanya owner dapat mengunggah, dan jangan memproses file tidak tepercaya di lingkungan produksi tanpa isolasi tambahan. Tampilan daftar hanya metadata; hapus dari database tidak menghapus backup atau data yang telah dikirim ke provider. Jangan unggah rahasia. Uji pengetahuan mencari kata dalam cuplikan dan mengirim hingga tiga cuplikan dengan pertanyaan ke provider setelah konfirmasi. Pencarian bukan semantik; nama sumber yang ditampilkan adalah kandidat, bukan bukti jawaban benar. Dokumen dapat berisi prompt injection; filter ini tidak menjamin AI mengabaikan instruksi berbahaya. Akses chat anggota nonaktif secara default dan diaktifkan terpisah oleh owner seperti dijelaskan di atas.

Tools owner menyediakan ringkasan, terjemahan Indonesia/Inggris dan tinjauan klaim dengan konfirmasi. Tinjauan bukan pemeriksaan fakta berbasis sumber. Pencarian web tersedia melalui Brave Search jika `AI_BRAVE_SEARCH_KEY` diatur. Mode riset mengirim pertanyaan ke Brave lalu hingga tiga cuplikan ke provider AI, menampilkan tautan sumber kandidat; ini bukan pembacaan artikel penuh atau verifikasi fakta dan dapat keliru. Dua langkah memakai kuota terpisah serta berpotensi berbiaya. Mode rangkuman tautan mengambil halaman HTTPS publik tanpa redirect, maksimal 128 KB HTML/teks UTF-8, lalu mengirim maksimum 2.500 karakter ke provider. Alamat DNS diperiksa dan koneksi dipin ke alamat publik, tetapi proteksi ini bukan audit keamanan lengkap. URL bertanda tangan atau berisi rahasia jangan digunakan; situs target menerima permintaan. Video YouTube memerlukan transkrip yang ditempel; tidak ada pengambilan transkrip otomatis. Dokumentasi: https://api-dashboard.search.brave.com/documentation/services/web-search . Data yang dikirim diproses provider dan fallback; hasil bisa salah. Tidak ada penyimpanan input dan hasil di modul tools.

## Gambar
Buat dan edit melalui OpenAI Images API jika owner mengisi `AI_IMAGE_API_KEY` dan `AI_IMAGE_MODEL` di environment server dan mengaktifkan fondasi AI. Model harus mendukung endpoint terkait; konfirmasi model dan akses pada dokumentasi OpenAI sebelum uji langsung: https://developers.openai.com/api/reference/resources/images/ . Satu gambar PNG per permintaan dengan pilihan 1024×1024, 1536×1024 atau 1024×1536 sesuai dukungan model; gaya dipilih sebagai instruksi prompt, bukan jaminan hasil; edit menerima input PNG maksimum 1,5 MB dan dimensi maksimum 2048. Prompt dan input dikirim ke OpenAI setelah konfirmasi; hasil PNG dikembalikan ke browser tanpa disimpan bot. Batas ukuran dan header bukan validasi keamanan PNG menyeluruh. Tidak ada fallback gambar, penyimpanan hasil oleh bot atau dukungan file input lain. Kuota AI bersama dihitung sebelum panggilan; biaya dapat berbeda dari teks. Timeout 120 detik, satu permintaan gambar per proses; ini bukan batas biaya.

## Server Builder
Owner membuat rencana dari deskripsi dan meninjau JSON tervalidasi. Hanya pembuatan maksimal 5 kategori, 15 channel teks/suara dan 5 role baru; tidak ada penghapusan atau pengeditan objek yang ada. Tidak ada izin khusus untuk role yang dibuat; channel mewarisi izin bawaan kategori/server dan mungkin terlihat oleh semua anggota. Penerapan memerlukan konfirmasi tersendiri, izin bot dan rencana yang masih berlaku, satu kali, maksimal 5 menit. Tidak ada rollback otomatis. Bila terjadi error/timeout, sebagian objek mungkin telah dibuat bahkan jika respons Discord tidak tiba; periksa daftar hasil dan server sebelum tindakan berikut. Cache Discord mungkin tidak lengkap dan proses paralel berbeda tidak terkoordinasi. Rancangan hanya di memori dan hilang setelah restart. Jangan gunakan pada server produksi sebelum diuji langsung.

## Masih terbatas
Integrasi inti tersedia dengan batasan di atas, bukan semua opsi desain awal: poin Activities bukan wallet ekonomi; proaktif hanya satu icebreaker harian; memori hanya sementara per channel/DM; multimodal gambar/audio/file dibatasi sesuai penjelasan di atas; OCR berbasis model vision hanya untuk gambar, bukan PDF scan langsung; beberapa tab preview tetap simulasi. Provider vision, Discord, PostgreSQL nyata, deployment dan resource Wispbyte belum diuji. Jangan menganggap fitur parsial sebagai implementasi semua opsi UI awal. Uji langsung ditunda ke Tahap 9. Zod telah dimigrasikan dari v3 ke v4 untuk GHSA-mrhx-c7xc-m3w5 dan skema record diperbarui. `npm audit --omit=dev` melaporkan 0 advisory pada saat pengujian; data advisory bisa berubah. Pengujian kompatibilitas hanya mencakup contoh skema guild, ekonomi, dan input command; perilaku error dan default optional Zod v4 dapat berbeda, jadi verifikasi seluruh jalur pada Tahap 9 sebelum produksi.
