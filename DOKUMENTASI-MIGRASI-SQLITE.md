# Migrasi SQLite — fondasi eksperimental, belum untuk deployment

**Status:** belum tersedia sebagai pilihan database saat startup. Aplikasi masih menggunakan PostgreSQL dan fallback RAM yang sudah ada; tidak ada perubahan default. Jangan mengonfigurasi Wispbyte untuk SQLite berdasarkan kode ini atau menganggap tahap 8 selesai. Jangan gunakan backend SQLite eksperimental untuk data produksi.

Fondasi awal `src/services/storage/sqlite.js` menggunakan `node:sqlite`, file SQLite, WAL, foreign keys, busy timeout dan transaksi `BEGIN IMMEDIATE` sinkron dengan rollback. Callback transaksi harus sinkron dan tidak boleh melakukan panggilan jaringan, Discord, provider, atau I/O eksternal. `DatabaseSync` memblokir event loop selama query atau busy timeout: batasi ukuran dan durasi transaksi; ini bukan bukti aman untuk beban produksi Wispbyte.

Adaptasi **belum tersambung ke startup**: uji lokal memakai adapter eksplisit; API penyimpanan AI foundation/welcome/chat/knowledge/Activities dan transaksi ekonomi mengenali adapter tersebut. Poin Activities masih terpisah dan belum terhubung ke wallet. Adapter belum mencakup API umum bot, dashboard, wipe, legacy, backup, migrasi data, semua writer ekonomi, ataupun jalur SQL lainnya. Contoh pemanggilan dan pilihan path tidak disediakan sebagai konfigurasi deployment karena tidak lengkap.

Tes fondasi menggunakan file sementara dan proses terpisah, bukan mock SQLite: jalankan `node --test tests/sqlite-foundation.test.js` dengan Node 22.13+ (diverifikasi dengan 22.23.5). `node:sqlite` masih dapat memberi peringatan eksperimental. Suite lama `node --test tests/tahap{5,6,7,8}*.test.js` juga harus lulus.

Sebelum beralih: audit seluruh jalur baca/tulis dan transaksi termasuk role premium dan penghapusan; rancang migrasi versi skema, driver/API lengkap serta pengecekan versi dan kegagalan startup tanpa fallback RAM; tes kompetisi lintas proses, restart, rollback, data lama dan seluruh fitur; pastikan satu lokasi file persisten dengan izin terbatas; pastikan backup konsisten menggunakan SQLite backup API atau snapshot yang aman dengan database berhenti, termasuk WAL, dan uji restore. Mengopi file `.db` saja saat WAL aktif bisa menghasilkan backup tidak konsisten. Verifikasi kapasitas, latensi, filesystem dan persistensi Wispbyte saat tahap 9.

PostgreSQL ke SQLite **tidak otomatis dimigrasikan**. Bila ada data PostgreSQL, hentikan semua writer, buat dan verifikasi backup, gunakan prosedur ekspor/impor teruji yang mencakup seluruh tabel, key legacy, TTL dan relasi, bandingkan data dan uji restore sebelum cutover. Belum ada skrip migrasi yang aman untuk digunakan. Jangan menjalankan bot dengan dua backend aktif pada data sama; jangan menyatukan reward sampai semua writer ekonomi memakai transaksi yang sama.
